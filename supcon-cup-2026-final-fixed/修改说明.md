# 修改说明（fixed 副本）

本目录是 `sherlock-miller/supcon-cup-2026-final`（GitHub main）的修改副本。
修改内容 = 代码审查结论（任务二六个严重问题 + 相机 SDK 问题）的落地修复。
任务二不采用手写修补，而是整体整合已经写好的独立方案（原 `requirements-dev/` 目录）。

## 一、任务二：整段替换为 task2_service 实现

新增：

- `final_algo_service/task2_service/` — 任务二独立包（config/controller/vision/camera/ocr/geometry/hardware/models）
- `final_algo_service/config.json` — 任务二现场配置（全部关键坐标为 `__现场标定后填入__` 占位，
  占位未填完时 `load_config` 直接拒绝；`service.allow_motion=false` 默认锁定真机运动）
- `final_algo_service/tests/test_geometry.py`、`test_ocr.py`、`test_task2_controller.py` — 配套测试

删除：

- `final_algo_service/tasks/task2_cubes.py` — 旧实现（数字绑死预设槽位、枚举补全猜数字、
  单一放置点、无姿态保持、部分完成也报成功）
- `final_algo_service/tests/test_cube_completion.py` — 它断言的"枚举补全"正是被删除的错误行为

接线：

- `final_algo_service/app.py` 的 `POST /api/task2/execute` 改为调用
  `task2_service.controller.Task2Controller`（懒加载运行时 + 并发互斥锁），
  返回 `{success, message, completedDigits, elapsedMs}`，竞赛软件仍只看 `success`。
- 配置文件路径默认 `final_algo_service/config.json`，可用环境变量 `TASK2_CONFIG` 覆盖。

六个问题的对应关系：

1. 数字↔槽位错绑 → 新方案按"四个真实物理槽位 ROI"识别数字在哪个槽，抓该槽的示教抓取位；
2. 枚举补全猜数字 → 已删除；识别不全自动重拍（`recognition_attempts` 次），仍不全返回失败；
3. 无深度/手眼 → 默认"固定槽位示教抓取"不依赖手眼；可选 `use_rgbd_refinement=true`
   启用深度+手眼精修（占位手眼矩阵时配置层拒绝启用）；
4. 单一放置点 → `destination_slots` 四个互不重叠放置点，配置层强制四点坐标不同；
5. 无姿态保持 → `preserve_source_orientation=true`：放置用抓取的 roll/pitch + 源 yaw；
6. 部分完成报成功 → 任何一步失败即停，`completed != [1,2,3,4]` 一律 `success=false`。

另外新增：每次放置后拍照验证（源槽变空 + 目标点有物 + 数字正确，可在配置里关）、
每次运动前 `plan_only` 预规划、OMPL 回退即拒绝执行、安全盒硬拒绝。

## 二、相机：三处统一改为 pyorbbecsdk2

pip 包名 `pyorbbecsdk2`（import 名 `pyorbbecsdk`）。旧代码用的是 v1 写法
（`enable_video_stream()` 等），在 v2 里不存在，初始化即 AttributeError。

- `final_algo_service/task2_service/camera.py` — 方案自带，已是 v2（帧同步 + D2C 对齐 +
  depth_scale + 设备真实内参 + 尺寸一致性检查）。
- `final_algo_service/vision/camera.py`（task1/3 直连模式）— 重写 Orbbec 路径为 v2，
  加帧同步、D2C 对齐、depth_scale（深度输出改为 float32 毫米）、D2C 后尺寸校验；
  新增 `get_color_intrinsics()`；`close()` 现在会真正释放管线并可自动重开。
  远程模式（CAMERA_SERVER_URL）与 CV2 兜底未动。
- `相机服务/camera_server.py` — OrbbecCam 改为 v2 + D2C 对齐 + depth_scale
  （深度以 uint16 毫米传输，消费端无需改）。

设备占用互斥：同一台 Gemini335 同一时间只能被一个管线占用。`app.py` 里
task1/3 结束后自动 `CameraWrapper.close()`，task2 结束后自动 `camera.stop()`，
三个任务可串行执行。真机首验时注意观察切换日志。

## 三、依赖与部署

- `requirements.txt` 增加 `pyorbbecsdk2>=2.0.0`；
- `download_wheels.sh` 下载包名 `pyorbbecsdk` → `pyorbbecsdk2`；
- `Dockerfile` 增加 `COPY task2_service/ config.json`。
- ⚠️ Docker 部署的限制：Windows Docker Desktop 无法访问 USB 相机，task2_service
  的采集器只有直连模式——**任务二要求算法服务原生运行在插相机的机器上**
  （task1/3 仍可走远程相机服务）。如需容器内跑任务二，要给 task2_service/camera.py
  加远程模式（未做）。
- 任务二 OCR：EasyOCR（仅英文模型、`download_enabled=false` 离线）+ Tesseract +
  OpenCV 模板匹配三路投票，任一路缺失自动降级；不再依赖 torch/Grounding DINO/CLIP。
