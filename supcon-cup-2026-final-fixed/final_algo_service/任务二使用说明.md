# 任务二使用说明（整合版）

任务二已整合进本算法服务（`final_algo_service/`），由 `task2_service` 包实现：
识别标有 1、2、3、4 的四个长方体当前所在的真实物理槽位，严格按 1→2→3→4 抓取，
放到四个互不重叠的目标位置，四个全部成功才返回 `success=true`。

## 程序怎样工作

1. 机械臂到安全位，再到固定拍照位。
2. 相机一次取得对齐的彩色图和深度图（pyorbbecsdk2，帧同步 + D2C 对齐）。
3. 程序分别检查四个"真实物理槽位"的 ROI，识别每个槽位当前放的是哪个数字。
4. 只有确认数字恰好为 1、2、3、4 且不重复时才允许运动；识别不全会重拍，绝不猜缺失数字。
5. 按数字顺序，从识别出的实际槽位抓取，放到四个不同目标位置；保留抓取时的完整姿态（roll/pitch/yaw），避免碰撞和重叠。
6. 每放一个，再拍照检查源槽已空、目标点有物体且数字正确。四个全部成功才返回 `success=true`。

## 启动

在插着 Gemini335 相机的机器上（任务二相机为 USB 直连模式，Docker 容器内无法访问 USB）：

```powershell
cd final_algo_service
python -m pip install -r requirements.txt
python app.py
```

官方比赛软件调用：`POST http://<本机IP>:5000/api/task2/execute`，请求体 `{}`。
任务二有自己的机械臂/灵巧手地址配置（`config.json` 的 `arm.base_url` / `hand.base_url`），
与 task1/3 用的 `config.py` 相互独立，以现场实际 IP 为准。

## 现场必须填写的参数

打开 `config.json`，搜索 `__现场标定后填入__`，全部替换为真实数值：

- 机械臂和灵巧手服务的真实 IP；
- 机械臂允许运动的安全盒范围（`arm.safe_box`）；
- 安全位（`arm.safe_pose`）和固定拍照位（`task2.photo_pose`）；
- 四个真实源槽的图中 ROI、各自抓取位姿、空槽深度（`task2.source_slots`）；
- 数字 1～4 的四个不同放置位姿、图中 ROI、空台深度（`task2.destination_slots`）；
- 灵巧手可靠抓紧长方体的 10 个关节归一化值（`hand.poses.grasp_block`）。

坐标 `x/y/z` 单位是米，`roll/pitch/yaw` 单位是弧度。ROI 是 `[左, 上, 右, 下]`，
全部用图像宽高的 0～1 比例。

默认采用更稳妥的"固定槽位示教抓取"：`use_rgbd_refinement=false`，不需要手眼矩阵。
若现场完成了可靠的手眼标定，才可填写 `calibration.t_end_camera` 并改为 `true`，
让深度图微调抓取坐标和方向。

空槽/空台深度的测量方法：物体未放入时在拍照位连续取多帧，记录对应 ROI 的深度中位数，单位毫米。

## 安全启用顺序

1. 保持 `service.allow_motion=false`，先填完参数（占位未填完服务会拒绝动真机）。
2. 启动后先确认任务一/三正常，再单独调一次任务二接口，看返回 message 里的配置错误提示。
3. 现场人员守在急停旁，先把速度保持在示例的低速值。
4. 确认安全盒、姿态、抓取点、放置点都正确后，最后才把 `allow_motion` 改为 `true`。
5. 重新启动程序，再用比赛软件调用赛题2。

程序对每个机械臂目标都会先 `plan_only=true` 预规划；如果服务器提示回退到 OMPL
非直线路径，程序会拒绝执行。运动中不要让第二个程序同时控制设备。

## 返回结果

成功示例：

```json
{"success": true, "message": "任务二完成……", "completedDigits": [1,2,3,4], "elapsedMs": 123456}
```

任何一步失败都返回 `success=false` 并停止后续动作，默认保持当前位置，等待现场人员
确认后处理。只有现场验证"任何已知失败状态下自动撤回都安全"以后，才可把
`task2.retreat_on_failure` 改为 `true`。
